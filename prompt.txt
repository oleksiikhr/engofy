# Engofy — Бачення продукту (brainstorm)

Вся розробка цього додатка відбувалась достатньо хаотично і UI треба переробити, можливо
разом з тим і саму логіку. Мета цього документа — продумати кожну сторінку і функціонал,
щоб продукт був дійсно корисний користувачу і формував звичку (addictive) навчання
англійської.

## Фінальний список сторінок

1. `/` — landing (guest) / feed (auth)
2. `/posts` — список статей з фільтрами
3. `/posts/[slug]` — сторінка поста (найскладніша логіка — обговорюємо останньою)
4. `/practice` — сесія інтервального повторення (слова+фрази+граматика впереміш, FSRS)
5. `/dictionary` — власні збережені слова/фрази (без глобального пошуку)
6. `/grammar` — вся граматика одразу, підсвітка "вчу" / "вивчено"
7. `/grammar/[slug]` — сторінка теми граматики
8. `/pricing` — тарифи (тільки guest)
9. `/login` — magic code (6-значний код) + Google One Tap; авто-реєстрація і логін в одному
10. `/profile` — профіль
11. `/profile/progress` — прогрес навчання
12. `/profile/subscription` — керування підпискою
13. Сторінка результату оплати (success/cancel) — стан, не окремий пункт навігації
14. `/terms`, `/privacy`
15. 404 / 500 — намальовані стани помилок, не окремі роути

Свідомо НЕ робимо (і чому):
- Сторінка реєстрації — вхід тільки через magic code / Google One Tap, реєстрація автоматична.
- Password reset / email verification — паролів нема взагалі.
- Глобальний пошук слова в `/dictionary` — тільки власні збережені слова/фрази.
- Leaderboard / рейтинг — нема змагального елементу окрім streak.
- `/contact` — досить посилання у футері.
- Теги/категорії постів — поки не існують.
- Окремі `/dictionary/my`, `/grammar/my` — на самих сторінках `/dictionary` і `/grammar` одразу
  показуємо "своє" (dictionary) або "все з підсвіткою свого" (grammar), без табів-роутів.

## Технічна довідка з бекенду (звірено з кодом, щоб не вигадувати заново)

- `learning_cards` — одна уніфікована SRS-картка (FSRS-алгоритм), вказує рівно на одне:
  word / phrase / grammar usage point (`src/modules/learning/domain/card-target.ts`).
- `GET /learning/practice`, `POST /learning/cards/:id/review`, `GET /learning/due-count`,
  `GET /learning/streak` — практика і стрік вже реалізовані на бекенді.
- `GET /dictionary` (бекенд) = список вже доданих карток користувача (word+phrase) — НЕ
  глобальний пошук слова. Глобальної query по `words`/`word_definitions` зараз нема.
- `GET /content/grammar`, `GET /content/grammar/:slug` — глобальний довідник граматики вже
  реалізований і не залежить від користувача.
- Фронтенд вже має `apps/web/src/pages/practice.astro` (+ e2e) — залишаємо назву `/practice`
  замість `/learn`, бо це точніше описує drill due-карток, а не "навчання" в широкому сенсі.

## Головна сторінка

Для гостей — landing page: секції з описом фіч, скріншотами, продуктовим описом (SaaS-style).
TODO деталі секцій.

Для авторизованих — НЕ стрічка постів (та вже є на `/posts`), а "Сьогоднішня сесія":
лінійна послідовність кроків без вибору з боку юзера (мета — прибрати параліч вибору,
одразу кинути в дію).

**Кроки сесії:**
1. **Пост.** Вибір — просте правило (без ML/рекомендатора): непрочитаний
   (`post_reads`) пост у діапазоні ±1 CEFR-рівня юзера (з onboarding), найновіший
   спочатку. Якщо під рівень нічого не лишилось — розширюємо діапазон CEFR.
2. **Практика, прив'язана саме до цього посту.** НЕ загальний due-queue, а тільки
   картки, чия ціль (word/phrase/grammar) зустрічалась у щойно прочитаному пості
   і due ≤ now. Рахується "наживо" в момент кроку (не фіксується заздалегідь!) —
   інакше не підхопить слова, додані юзером щойно під час читання (нова картка
   отримує `due = now` одразу, `FsrsService.newCard`). Педагогічний сенс: закріпити
   слово одразу після зустрічі в контексті (testing effect), поки свіже.
3. **Один grammar-хайлайт з цього ж посту** — завжди показуємо, коли є що показати.
   Одна конструкція з `grammar_matches` цього посту, яку юзер ще не засвоїв — короткий
   can-do + приклад, посилання "детальніше" на `/grammar/[slug]` (не примусово).
4. **Фінал.** Екран "На сьогодні все" зі streak-приростом і рядком-підсумком
   ("+3 нових слова · 1 конструкція вчиться"). Далі — м'який заклик "більше статей на
   `/posts`", не обов'язок.

**Звідки Головна відрізняється від `/posts`:** Головна = "працюй" (система вирішує),
`/posts` = "переглядай/шукай" (юзер вирішує сам).

**Зв'язок з `/practice` (загальний FSRS due-queue):** крок 2 денного плану — це
контекстний "гарячий" зріз тільки з сьогоднішнього посту, НЕ заміна `/practice`.
Due-картки з попередніх постів (бэклог) в денний план не входять — вони лишаються
на `/practice`, куди веде окремий бейдж "N due" (вже реалізовано,
`GET /learning/due-count`). Після оцінки на кроці 2 FSRS перепланує `due` як завжди —
картка повертається в загальний пул і випливе в `/practice` коли настане її час
(або сьогодні ж, якщо оцінка "Again").

**Технічно — нова таблиця `daily_plans`:**
```
daily_plans
  id, user_id, plan_date (UTC calendar day — той самий boundary, що й daily streak),
  post_id (FK -> posts), grammar_usage_point_id (nullable),
  completed_at (nullable), created_at
  UNIQUE (user_id, plan_date)
```
Find-or-create при першому заході за день (ідемпотентно, той самий "gap-filler"
принцип, що й пайплайн постів) — план на день незмінний. `card_ids` свідомо НЕ
зберігаються в таблиці (рахуються наживо на кроці 2, див. вище). Прогрес кроків
не дублюється окремими колонками — крок 1 виводиться з `post_reads`, крок 2 — з
`review_logs` за сьогодні; тільки `completed_at` — явна фіксація завершення всієї
сесії.

**Пасивна зустріч vs активний review:** просте зустрічання слова в тексті посту НЕ
впливає на FSRS-показники (`due`/`stability`/...) — тільки явна оцінка
(Again/Hard/Good/Easy) через review. Якщо слово в пості вже вивчається, але ще не
`due` — показуємо його в читанні пасивно (мітка "вже вчиш", без форми оцінки), без
форсованого дострокового повторення. У крок 2 з формою оцінки потрапляють лише
картки з посту, які реально `due ≤ now` в момент кроку.

**Ліміт нових слів/день (новачок з нуля словника — інакше перший же пост засипле
100+ карток):** глобальний добовий ліміт нових карток (`learning_cards.createdAt` =
сьогодні), не "на пост" — бо юзер може додатково почитати щось із `/posts` того ж
дня понад денний план. Стартове число — **~12-15** (консенсус SRS-спільнот про
здоровий обсяг нових карток/день, для новачка ближче до нижньої межі).
Пріоритизація кандидатів зі схемою, що вже є (нових полів не треба):
1. `word_definitions.cefr_level` ≤ рівень юзера (не тягнути лексику вище рівня, яка
   випадково трапилась у тексті).
2. Серед них — сортування по `words.frequency_rank` (частотніші слова спочатку).
3. Обрізати на ліміті.
Механізм "юзер сам виключає вже знайомі слова під час читання" (тап/чекліст/щось
інше) — частина рідер-сторінки, дизайнимо там.

**Спрощена оцінка для першого показу нового слова:** замість 4 кнопок
(Again/Hard/Good/Easy) — 2 кнопки "Вивчив"/"Повтор", що мапляться на Good/Again
всередині (FSRS все одно рахує рейтинг, просто новачок не може усвідомлено
відрізнити Hard від Good на першому показі). Повна 4-бальна шкала лишається для
звичного `/practice`, де юзер вже має досвід із карткою — фіналізуємо це рішення
при детальному обговоренні `/practice`.

**Знайдений баг (не редизайн, треба фіксити незалежно від нього):** у поточній
`/practice` кнопка "Show answer" для слів/фраз нічого не показує — `secondary` в
`PracticeQueueItem` захардкожений як null для word/phrase ("null for words/phrases
in V1"), хоча `WordDefinition.definition`/`phonetic`/`exampleSentence` вже існують і
заповнюються enrichment-пайплайном. Юзер зараз оцінює себе наосліп для слів/фраз;
для граматики працює (can-do statement). Механіку самого review-екрану (flip-card
vs contrastive-питання) редизайнимо при обговоренні `/practice`.

**Наскрізна тема на майбутнє (grammar mastery):** мета — щоб юзер зазубрював усі
usage points кожної граматичної конструкції настільки, щоб вільно розрізняв схожі
конструкції в контексті (напр. Present Continuous vs "going to"). Дані це вже
підтримують (`grammar_usage_points` — окремий guideword+can-do на кожен пункт).
Питання дизайну практики/опитувань (contrastive-питання між схожими конструкціями)
— повертаємось при обговоренні `/practice` і `/posts/[slug]`.

## Сторінка /posts

Зараз не існує взагалі (є тільки `/` без фільтрів, `GetFeedQuery` приймає лише
`limit`/`offset`) — чисте поле. Призначення: архів + самостійний пошук ("посидіти,
повибирати"), на відміну від Головної, де систему обирає сама. Працює і для гостей
(PLAN.md §2), просто без read-стану/персоналізації.

**Фільтри:**
- CEFR — chips A1..C2 + "Усі", multi-select.
- Пошук по слову/фразі — автокомпліт по `words.lemma`/`phrases.text`, фільтрує пости
  де слово реально зустрічається (join через `sentence_tokens.word_id`/`phrase_id`,
  той самий механізм, що вже рахує `posts` у `get-dictionary`, лише в інший бік).
  Тільки точна відповідність через індексовані дані — без вільного повнотекстового
  пошуку по title/body (нема інфраструктури, і не потрібно).
- "Тільки непрочитане" — toggle з `post_reads`, default off, недоступний для гостя.

**Сортування:** фіксовано найновіші → найстаріші, без UI-контролу зміни.

**Пагінація:** курсорна (keyset) на `(published_at, id)`, без limit/offset — закриває
і TODO, вже позначений коментарем у `get-feed.handler.ts` про нестабільність
поточної offset-пагінації.

**Картка посту в списку:** title, excerpt, CEFR-бейдж (рівень посту), дата,
позначка "Прочитано" якщо є в `post_reads`. Без лічильника "N нових слів для тебе"
у V1 (свідомо спрощено).

Дизайн/верстка — окремий прохід разом із загальним редизайном усіх сторінок, не
зараз.

## Сторінка /practice

Загальна SRS-черга (слова + фрази + граматика разом), одна картка за раз, оцінка
Again/Hard/Good/Easy. Базова механіка вже реалізована — нижче виправлення й уточнення.

**Архітектурна зміна: SRS-таргет слова = `word_definition_id`, не `word_id`.**
Слово може мати кілька значень за частиною мови ("run" — дієслово і іменник),
і рідер вже знає, яке саме значення юзер зустрів (`WordAnnotationView` несе
`wordDefinitionId` окремо), але `learning_cards` досі зберігає тільки `wordId` —
загальний, без прив'язки до сенсу. Це свідомий вибір із минулої сесії (PLAN.md
§17 B2, коментар `WordAnnotationView`), який тепер свідомо переглядаємо, бо він
конфліктує з рештою системи: `/dictionary`-view вже очікує POS на рівні картки
(`secondary` поле), і саме це, ймовірно, причина нестабільного e2e-тесту
`/dictionary`, згаданого в PLAN.md §17 B5. Прода немає — переробляємо без міграції.

Зміни:
- `learning_cards.word_id` → `word_definition_id` (FK -> `word_definitions`),
  unique-констрейнт і CHECK "exactly one target" відповідно.
- `CardTarget`/`CardTargetInput` — тип `'word'` резолвиться через `wordDefinitionId`.
- `AddCardHandler` — валідація цілі йде проти `WordDefinition`, не `Word`.
- Кнопка "+" у рідері — тривіально: `wordDefinitionId` вже є в
  `WordAnnotationView`, просто відправляємо його замість `wordId`.
- Фронт картки в `/practice` — показувати частину мови поруч зі словом
  ("run (v.)" / "run (n.)"), бо тепер та сама лема може бути двома незалежними
  картками — інакше виглядатиме як дублікат.
- `/dictionary`, сайдбар у `get-post-detail` — прямий join через
  `word_definition_id`, без непрямого резолву через `Word`.

**Стани сторінки:**
- Порожньо (юзер ще не додав жодної картки) — окремий екран від "все пройдено":
  CTA веде на `/` чи `/posts` почати читати, а не просто "повернись пізніше".
- Сесія — над карткою короткий summary "X due · Y нових" (не тільки лічильник
  "залишилось" на самій картці), кольоровий/іконний бейдж під тип, клавіатурні
  шорткати (пробіл — показати відповідь, 1-4 — оцінка).
- Завершення — явно пояснювати причину, якщо нових карток показано менше, ніж
  юзер додав ("12 нових пройдено сьогодні · ще N розблокується завтра"), інакше
  виглядає як баг, а не як свідомий ліміт.

**Reveal-контент при "Show answer" (баг, знайдений раніше — тепер вирішується
разом з архітектурною зміною вище і суттєво підсилюється):**
- Word/Phrase — визначення+фонетика з конкретного `WordDefinition`/`Phrase`
  (однозначно, завдяки зміні на `word_definition_id`), **АЛЕ приклад-речення —
  не AI-generated `exampleSentence`, а реальне речення з останніх 3 прочитаних
  постів**, де слово/фраза реально зустрічається (`sentence_tokens.sentenceId`
  → `sentences.rawText` → `posts`, обмежено `post_reads`, сортування
  `readAt desc`). Фільтрується ще й по POS токена (не будь-яке вживання леми, а
  саме той сенс, що на картці). Показуємо 1 речення одразу, ще до 2 — через
  кнопку/tooltip (дизайн пізніше). **Без fallback** — якщо серед прочитаних
  постів немає підходящого речення, приклад просто не показуємо (ні AI-приклад,
  ні речення з непрочитаного посту) — з'явиться саме собою, коли юзер прочитає
  ще один пост із цим словом. Enrichment (Track A) лишається потрібним для
  визначень/CEFR — приклад-речення з нього більше взагалі не показуємо в
  practice.
- Коли речення підтягнулось із прочитаного посту — **явно підсвічуємо джерело**
  (напр. невелика мітка "зі статті, яку ти читав" з посиланням на пост), а не
  просто показуємо голе речення без контексту, звідки воно.
- Grammar — `canDoStatement` + `exampleText` + той самий принцип реального
  речення з контексту (`grammar_matches` → sentence), плюс окремий шаблон
  картки (див. нижче).

**Аудіо-вимова:** 🔊 кнопка біля слова/фрази — `Web Speech API`
(`speechSynthesis.speak`, `en-US`/`en-GB`), клієнтський виклик без бекенду/файлів,
досить для MVP. Бонус: та сама кнопка може озвучити і контекстне речення.

**Фільтр за типом картки:** chips "Слова / Фрази / Граматика", multi-select,
default всі активні — той самий патерн, що й CEFR-чипси на `/posts`.

**"Хочу більше" — обхід денного ліміту нових карток за явним запитом юзера:**
денний ліміл (~12-15) — м'який дефолтний пейсинг, не жорстка стеля. На екрані
завершення сесії — кнопка "Показати ще N нових слів", яка свідомо перевищує
ліміт на цю сесію. Єдине жорстке обмеження, що лишається, — загальний free-tier
ліміт 100 карток сумарно (Premium — без стелі). Review/relearning і так завжди
показуються всі — "більше" стосується тільки нових.

**Окремий, багатший шаблон картки для граматики** (свідомо, не той самий, що
word/phrase — значно більше інформації): кикер = категорія + назва конструкції
("PRESENT" · "Present Continuous"), фронт = guideword, reveal = can-do statement
+ реальне речення з контексту + посилання "Детальніше" на `/grammar/[slug]` (де
вже лежить повна шпаргалка `cheat_sheet_content` — не дублюємо в картці).

**Ліміт нових карток у черзі — throttle на рівні `/practice`, не на "+"-кліку:**
"+" можна тиснути вільно (єдине обмеження — загальний free-tier ліміл 100 карток
сумарно). Черга `/practice`: due review/relearning-картки показуються завжди
повністю (час іде, тут не можна економити), картки в стані New — не більше
